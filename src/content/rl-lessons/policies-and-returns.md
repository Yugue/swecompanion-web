# 1.5 Policies, returns, discounting, and episode boundaries

## 1. A policy specifies behavior

A **stochastic policy** pi(a given s) assigns action probabilities in a state. A **deterministic policy** mu(s) selects one action. Both can be tables or parameterized functions.

A policy describes how to act; a reward describes the consequence to optimize. A policy can change during training even if the task reward remains fixed.

## 2. Return combines future rewards

\[
G_t=\sum_{k=0}^{T-t-1}\gamma^k R_{t+k+1}
\]

G at time t is the discounted return until episode end T. R is a reward, k counts steps into the future, and gamma is the discount factor between zero and one. Continuing discounted tasks use an infinite sum, commonly with gamma strictly below one and bounded rewards.

Rewards 2, 0, and 10 with gamma=0.9 give G0=2+0.9×0+0.81×10=10.1. The immediate reward receives no discount.

## 3. Discounting changes what is preferred

Gamma=0 values only the next reward. Larger gamma gives distant rewards more influence. For a constant reward stream, the sum is r/(1−gamma), which explains why larger gamma also increases typical value scales.

The rough **effective horizon** 1/(1−gamma) is 10 steps at 0.9 and 100 at 0.99. It is a weighting scale, not a hard cutoff or a promise that dependencies beyond it are learned.

Discounting can express a preference for earlier outcomes and facilitate well-defined objectives. It is not solely a numerical stabilization trick.

## 4. State the objective explicitly

\[
J(\pi)=\mathbb E_{S_0\sim\rho_0,\,\tau\sim\pi}[G_0]
\]

J is expected performance, rho zero is the initial-state distribution, and tau is a trajectory generated by the policy and environment. Training aims to improve J, not maximize every immediate reward independently.

Finite-horizon tasks can use gamma=1 when returns are well defined. A continuing **average-reward** objective instead measures long-run reward per step. It differs from discounted return; this guide primarily uses episodic and discounted objectives rather than treating their rankings as identical.

## 5. Termination is not external truncation

| Boundary | Meaning | Continuation value |
|---|---|---|
| Genuine terminal state | The modeled task has ended | Zero |
| External collection time limit | Interaction stopped while the task continues | Usually bootstrap |
| Genuine finite task deadline | Time is part of the task | Zero at that deadline |

At a genuine terminal state, no further task reward remains. At a rollout boundary or external time limit, the estimated continuation can still be nonzero. Use the final observation before reset when bootstrapping a truncated transition.

## 6. A numerical boundary check

Suppose reward is 1, gamma=0.9, and the successor value is estimated as 5. A continuation target is 1+0.9×5=5.5. A genuinely terminal target is 1. Confusing these introduces a systematic error of 4.5 in this example.

```python
continuation = 0.0 if terminated else next_value
target = reward + gamma * continuation
```

This snippet assumes next_value comes from the actual successor, not an automatically reset observation. Trace recursion may also need to stop at truncation even when the final value is bootstrapped.

## 7. Compute a return backward

The recurrence Gt=R(t+1)+gamma G(t+1) makes return computation efficient. Starting with zero beyond a genuine episode end, process rewards in reverse order:

```python
ret = 0.0
for reward in reversed(rewards):
    ret = reward + gamma * ret
```

Reward scale affects target magnitudes and optimization. Multiplying all rewards by a positive constant preserves an unregularized task's policy ranking, but may require retuning learning rates or regularization coefficients.
